# نظام نقطة البيع — POS System

نظام نقطة بيع متكامل مبني على Node.js و Express و PostgreSQL.

---

## متطلبات التشغيل

- **Node.js** 18 أو أحدث
- **PostgreSQL** 14 أو أحدث (قاعدة بيانات خارجية أو مُدارة)

---

## النشر على Hostinger (Managed Node.js)

### 1. رفع الملفات

ارفع محتوى هذا المجلد إلى استضافتك عبر:
- **Git**: اربط المستودع من لوحة Hostinger → Git → Deploy.
- **FTP/SFTP**: ارفع جميع الملفات (باستثناء `node_modules/`) إلى مجلد التطبيق.

> **مهم**: لا ترفع مجلد `node_modules/`. سيتم تثبيت الحزم تلقائياً من `package.json`.

### 2. ضبط متغيرات البيئة

في لوحة Hostinger → **Node.js** → **Environment Variables**، أضف المتغيرات التالية:

| المتغير | القيمة | ملاحظة |
|---------|--------|--------|
| `DATABASE_URL` | `postgresql://user:pass@host:5432/db` | رابط قاعدة البيانات (مطلوب) |
| `SESSION_SECRET` | سلسلة عشوائية طويلة | انظر كيفية توليدها أدناه |
| `NODE_ENV` | `production` | مطلوب لتفعيل وضع الإنتاج |
| `BASE_PATH` | `/` | مسار التطبيق (اتركه `/` إذا كان على الجذر) |
| `PORT` | يُضبط تلقائياً | لا تغيّره إلا إذا طُلب منك |

**توليد SESSION_SECRET:**
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 3. تثبيت الحزم وتشغيل التطبيق

Hostinger تُشغّل التطبيق تلقائياً عبر أمر `start` في `package.json`:

```bash
npm install --omit=dev
npm start
```

يمكنك أيضاً تحديد هذه الأوامر في لوحة Hostinger → **Node.js** → **Run command**.

### 4. إعداد قاعدة البيانات

التطبيق يُنشئ جداوله تلقائياً عند أول تشغيل. لا حاجة لتشغيل أي migrations يدوياً.

يتم إنشاء حساب مدير افتراضي:
- **اسم المستخدم**: `dr.shahin`
- **كلمة المرور**: `255205`

> **غيّر كلمة مرور المدير فور أول تسجيل دخول** من صفحة الإعدادات.

### 5. التحقق من التشغيل

بعد النشر، افتح رابط التطبيق في المتصفح. إذا ظهرت صفحة تسجيل الدخول فالتطبيق يعمل بنجاح.

## متغيرات البيئة — تفاصيل

انسخ ملف `.env.example` إلى `.env` واملأ القيم:

```bash
cp .env.example .env
```

| المتغير | الوصف | مطلوب |
|---------|-------|-------|
| `DATABASE_URL` | رابط اتصال PostgreSQL الكامل | ✅ نعم |
| `SESSION_SECRET` | مفتاح سري لتشفير الجلسات | ✅ نعم (في الإنتاج) |
| `NODE_ENV` | `production` أو `development` | موصى به |
| `PORT` | المنفذ الذي يستمع عليه الخادم (افتراضي: 3000) | لا |
| `BASE_PATH` | مسار URL الأساسي (افتراضي: `/pos-system`) | لا |

## هيكل المجلدات

```
pos-system/
├── server.js          # نقطة دخول التطبيق الرئيسية
├── db.js              # اتصال قاعدة البيانات والمخطط
├── package.json       # تبعيات المشروع وأوامر التشغيل
├── .env.example       # نموذج متغيرات البيئة
├── views/             # قوالب EJS لصفحات التطبيق
├── static/            # ملفات ثابتة (CSS، صور، uploads)
│   └── uploads/       # مجلد صور المنتجات المرفوعة
└── templates/         # قوالب HTML قديمة (غير مستخدمة)
```

---

## التشغيل محلياً (للتطوير)

```bash
# 1. تثبيت الحزم
npm install

# 2. نسخ وتعبئة متغيرات البيئة
cp .env.example .env
# عدّل .env بقيمك الفعلية

# 3. تشغيل الخادم
npm start
```

ثم افتح المتصفح على `http://localhost:3000`.

---

## الأمان في الإنتاج

- يفشل التطبيق عند البدء إذا كان `SESSION_SECRET` أو `DATABASE_URL` غير مضبوط في وضع `production`.
- ضع `NODE_ENV=production` دائماً على الخادم.
- غيّر كلمة مرور المدير الافتراضية فور التشغيل.
- تأكد من أن `static/uploads/` محمي من تنفيذ الملفات (Hostinger تفعل هذا تلقائياً).
